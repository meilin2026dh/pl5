# PL5 V0.3 指标时序模式反延续过滤引擎

> 研究原型：在 V0.2 `D:\pl5` 项目上增量扩展。保留 V0.2 的基础概率模型、统计证据门控、CSV 数据导入、算法研究与封存验证功能。本版本新增指标规则模块，官方数据必须由使用者从官方来源核对并导入；项目没有声称自动获取了已核验的真实开奖数据。

## 1. 目的与边界

把“对某个指标查看最近 N 期是否重复、有序、周期或交替，再剔除导致下一期同类模式延续的候选号”抽象为五个独立模块：

1. **指标定义** `indicator`：将每期五位号码映射为一个数，支持和值、跨度、奇偶个数、各位置数字、首尾差、重号、位置比较等。
2. **指标变换** `transform`：原值、模2、模3、模5、模10，例如和值尾数、和值奇偶。
3. **时序模式** `pattern`：连续相等、严格递增/递减、等差推进、2期/3期周期、升降交替、低多样性。
4. **触发方式** `mode`：`continuation` 要求最后 W 期已满足规律，候选下一期使之继续；`recurrence` 要求最近 lookback 期有该规律，候选下一期让相同类型模式再次出现。
5. **执行与审计**：对10万个候选逐一计算指标，合并命中的规则，并限制单条和累计过滤比例。所有规则输出历史片段、禁用指标值、理论删除数量和被执行的状态。

**重要：随机序列也会频繁形成看起来有规律的局部片段。公平独立开奖时，任意依赖历史的过滤器只要保留 K 个号码，其下一期精确命中概率仍为 K/100000。** 禁止把删除率高误读为预测率高。

## 2. 已实现指标

- 单期指标：`sum` 和值，`span` 跨度，`odd_count` 奇数个数，`high_count` 大数个数，`unique_count` 不同数字个数，`adjacent_equal` 邻位相同次数，`adjacent_up/down` 邻位上/下行次数，`adjacent_consecutive` 邻位差1次数，`max_frequency` 最高重复次数，`first_last_gap` 首尾差，`head_sum` 前两位和，`tail_sum` 后两位和，`middle_sum` 中三位和，`even_position_sum` 偶数位之和，`odd_position_sum` 奇数位之和，`mirror_pairs` 对称位置重合数，`inner_span` 内部跨度，`digit_1` 至 `digit_5` 各位值。
- 跨期指标：`same_positions_prev` 与上期同位置相等位数，`same_parity_positions_prev` 同位置奇偶一致位数，`digit_overlap_prev` 多重数字重合个数，`sum_delta_prev` 与上期和值变化量，`span_delta_prev` 与上期跨度变化量，`lastdigit_delta_prev` 与上期末位变化量。
- 用户可以在本地代码中注册新指标，但**不得直接执行网页或论文中由模型生成的未经审查的源代码**。

## 3. 模式定义和例子

| 模式 | 已知指标序列 | 被剔除的下一期指标 | 备注 |
|---|---|---|---|
| `constant` 连续同值 | 12、12、12 | 12 | 阻止连成4期 |
| `strict_up` 严格递增 | 12、15、18 | 大于18 | 删除比例可能很高，受护栏限制 |
| `strict_down` 严格递减 | 18、15、12 | 小于12 | 同上 |
| `arithmetic` 等差推进 | 12、15、18 | 21 | 公差持续 |
| `period2` 两期周期 | 3、8、3、8 | 3 | 阻止 ABABA |
| `period3` 三期周期 | 1、5、3、1、5、3 | 1 | 阻止 ABCABCA，需要窗口 ≥ 6 |
| `zigzag` 升降交替 | 1、4、2、5 | 小于5 | 阻止继续交替 |
| `few_distinct` 低多样性 | 1、2、1、2 | 1或2 | 非默认模式，容易剔除过多 |

`recurrence` 模式例子：最近5期“1、1、1、2、2”，历史出现过三期同值；候选下一期指标为2就形成新的三期同值，因此根据规则可标记剔除。它与要求最后三期已经全相同的 `continuation` 不同。

## 4. 数据接口

使用V0.2的 `pailie5.data.load_csv`，至少包含两列：

```csv
period,number
2026001,00128
2026002,90876
2026003,22014
```

文件从旧到新排列，数字期号会自动排序。真实数据的真实性必须通过官方公告人工核验及来源档案证明；不能仅凭文件名、模型生成内容或第三方站点认定。

**注意：跨期指标第一期无前一期，值缺失；在计算模式时采用后续各期的有效跨期值。**

## 5. 命令行

在项目目录中（Windows）运行：

```powershell
cd D:\pl5
uv sync --extra agent
uv run python pattern_cli.py --csv data\official_verified.csv --windows 3,4,6 --indicators sum,span,odd_count,unique_count,digit_5,same_positions_prev,sum_delta_prev --transforms raw,mod2,mod3 --backtest 50 --export runtime\pattern_candidates.csv --report runtime\pattern_report.json
```

`--mode continuation` 是末尾模式延续，`--mode recurrence --lookback 15` 为近期出现过同类模式后，再出现则标记剔除。增加 `--sum-min 15 --sum-max 35` 可叠加基础和值过滤。

若希望运行单独GUI：

```powershell
uv run streamlit run pattern_app.py
```

运行原界面 `uv run streamlit run phase2_app.py` 时，也可在多页面导航中进入“指标序列规则实验室”。

## 6. 扩充自定义指标

开发人员通过可信、经过测试的本地代码注册：

```python
from pailie5.pattern_rules import register_indicator, register_context_indicator

# 单期指标：五位数字的加权和
register_indicator("weighted_sum", lambda d: 1*d[:,0] + 2*d[:,1] + 3*d[:,2] + 4*d[:,3] + 5*d[:,4])

# 跨期指标：当前期百位与前一期百位是否相同
register_context_indicator("third_match_prev", lambda current,previous: (current[:,2] == previous[:,2]).astype(int))
```

然后在 `Configuration.indicators` 配置添加 `weighted_sum` 或 `third_match_prev`，即可自动应用所有已实现时序模式。前端手动列出的指标列表可后续接入本地注册表。

## 7. 过滤护栏

- `max_rule_remove` 默认0.65，单条规则超过65%直接跳过；大范围“持续递增/递减”尤其常见。
- `max_total_remove` 默认0.80，综合规则不能剔除超过80%，`min_keep` 默认1000，采用两项约束中更严格者。
- `max_rules` 每轮上限120，控制组合爆炸。
- 从删除范围小的规则开始依次应用；同指标变换下产生完全相同禁值集合的规则去重。
- 输出 `triggered`、`accepted_rules`、`excluded_rules`，并列出每条规则的原因。
- 基础过滤层属于用户另外指定的约束，与历史模式层相交；基础约束若太严格仍可导致候选集很小甚至为空，必须单独提示。

**护栏是工程资源和用户体验保护，不是数学上有利的过滤强度。**

## 8. 回测与科研升级方向

V0.3已实现向前滚动回测：验证第t期时只允许读取前t-1期；逐期对比实际保留次数与等规模随机候选集的理论预期。

目前回测给出 `z` 差异描述，但**没有进行大规模模型搜索所需的统一多重比较校正**，并且运行后若反复修改参数再检验同一数据将造成数据窥探。正式宣称发现优势前必须：

1. 按指标/变换/模式/窗口配置给每个规则登记唯一版本和先验实验计划；
2. 使用开发期数据选择规则、独立封存测试集和未来真实新增开奖做前向验证；
3. 以每期实际保留集合大小 K_t 对应的 K_t/100000 作为条件随机基线，不能只看历史过滤率；
4. 处理多重比较和动态参数调整；
5. 记录每条规则的独立贡献、失误剔除发生率、稳定性和可复现性；
6. 允许自动科研发现新指标或新模式，但**不允许未审计的外部代码直接进入正式运行环境**。

## 9. 文件清单

- `pailie5/pattern_rules.py`：计算所有指标、跨期指标、模式匹配、规则检测、护栏、回测。
- `pailie5/basic_filters.py`：基础指标上下限、允许/排除集合过滤及与时序规则交集。
- `pattern_cli.py`：命令行完整流程，CSV/JSON报告输出。
- `pattern_app.py`：网页可视化实验室（必须本机安装Streamlit方可执行）。
- `pages/01_指标序列规则实验室.py`：作为原Streamlit工作台的一个页面。
- `tests/test_pattern_rules.py`：独立单元测试及无未来数据泄漏测试。
- `examples/pattern_demo_report.json`：合成数据样例，**不是实际开奖研究结果**。

## 10. 项目建议

保留 V0.2 的基础概率算法，同时把V0.3规则引擎设为一个独立、可插拔的研究模块。未来自主科研中心通过受限的“指标描述+模式描述+实验参数”提交算法研究卡，经沙箱复现和样本外检验后，才能申请进入正式注册库。不要让LLM直接修改正在运行的过滤规则。
