# 排列五AI过滤智能体系统 V0.2｜第二阶段技术方案与验收报告

版本：0.2.0  
更新日期：2026-11-01  
项目性质：算法研究、检验设计、实验审计；非下注系统。

## 一、建设目标

从V0.1的“人工给模型、运行回测”，升级为“自动提出受限算法假设—预先规定评价规则—开发集竞争—封存集独立验收—记录研究知识”。本次提供真实数据的导入与联网社区适配器，但**尚未取得并核实全量官方真实数据，也未验证Mac上的LangGraph安装**。

不以提高中奖承诺作为成功目标。公平独立均匀开奖条件下，任意固定K个不同号码的覆盖概率为K/100000。只有长期、独立、锁定方法后仍出现超随机表现，才可提出进一步探查数据/机制异常的假设。

## 二、系统组成

| 构件 | 输入 | 核心功能 | 产出 |
|---|---|---|---|
| 数据代理 | 手动官方CSV / 第三方镜像 | 严格5位校验、规范期号、重复及冲突阻断 | 溯源库/数据指纹 |
| 假设代理 | 已注册DSL模板、可选LLM | 白名单模型提案、自动模型组合 | 算法参数JSON |
| 实验代理 | 历史开发集 | 按期滚动计算相对log似然、命中期数 | 开发集评估表 |
| 审计门控 | 开发集统计 | 单侧检验与Bonferroni、无证据时拒绝 | 允许/淘汰 |
| 封存评估代理 | 预注册选型、最后一段历史 | 一次性封存回测，禁止更改选模参数 | 独立验收结论 |
| 知识代理 | 全部研究状态 | 持久化来源、假设、检查点、结果 | SQLite研究知识库 |

技术栈：Python 3.12、NumPy、Pandas、SciPy、SQLite3，选装Streamlit（前端）、LangGraph/SQLite Checkpoint（图编排）、OpenAI Python SDK（可选有限JSON假设）。

## 三、数据可信性机制

**规范表：** `period,number`，号码保持字符串，且五位数字。期号 `26271` 归一到 `2026271`；跨来源重叠按规范期号比对。

**完整性：** 空号码、乱码、非五位长度、期号冲突会阻止入库；同号码在不同期出现则合法。

**可追溯性：** 来源登记表 `sources` 保存文件SHA-256与标签、导入时间、期数、起止期；`source_draws` 保留每个原始来源对应的记录；`draws` 是可用于实验的统一表。同一期不同开奖号码将整批拒绝。

**真实性限制：** 系统只能追溯“文件是从哪里被上传/抓取的”，无法证明用户上传CSV或社区镜像等同官方开奖；需人工官方公告交叉核验。无法联网的运行环境不假冒已同步最新数据。

## 四、安全受限的算法发现

完全开放的AI执行代码会存在注入、资源耗尽、跑偏、统计作弊风险，因此V0.2采用**算法描述语言DSL**：

```json
{
  "name": "DSL自动合成",
  "type": "blend",
  "components": [
    {"type": "pairwise"},
    {"type": "recency", "half_life": 100}
  ],
  "weights": [2, 1]
}
```

`type`只能是`positional`、`pairwise`、`ensemble`、`recency`、`blend`；`blend`最多3个非嵌套组件，权重整数1–5；时间衰减半衰期整数25–300。算法由确定性、可复现的本地评分函数执行。

在此约束下可通过固定种子生成两套混合架构，属于有限的**符号算法合成**；不能等同于“AI自动发明任意算法”。LLM只能建议符合JSON约束的参数，禁止代码执行。

## 五、时间划分与独立验证

设原始数据按期号从早到晚为 `D[0..N-1]`，预先规定：

- 开发测试块 `D[N-H-V : N-H]`，其中V为开发集期数；
- 封存测试块 `D[N-H : N]`，其中H为holdout_size；
- 模型对任意`t`的评分只能使用 `D[max(0,t-W):t]`，其中W是训练回看窗口；
- 开发选模完成后，才向SQLite写入`experiments`记录：数据指纹、算法DSL、K、W、V、H、随机种子及全部开发集证据；此时状态`sealed_pending`；
- 首次开封封存集时模型不再变化，可逐期读取之前已开奖的历史更新窗口，但不能重新选择模型；
- 完成后将状态原子写为`baseline_only_no_dev_evidence`、`no_verified_advantage`或`exploratory_signal_requires_replication`。

**防数据泄漏保证**仅针对当前实现和测试条件，不能防止研究者在外部系统查看历史开奖；务必遵循预注册和盲测纪律。

## 六、决策标准

对算法 j 在每个开发期的实际开奖号码 x_t，计算：

`gain(t,j) = log(p_j(x_t | D<t)) − log(1/100000)`

其中`p_j`是将该算法全部10万号码的评分通过归一化指数映射得到的概率，仅为指定模型的数学分布；不是已证明的真实中奖概率。

取开发集平均gain，计算探索性单侧正态近似p值，并乘以已检验候选模型总数进行Bonferroni校正。只有平均增益大于0且校正p<0.01时，才选出均值最高的一个候选进入封存集，否则**拒绝所有模型**、使用均匀随机对照。

封存集记录：K/100000理论覆盖率、命中期数、二项检验单侧p值、平均log增益与模型冻结方案；即使观察到探索性信号也仅标记“需未来复现”。这一研究门控非常保守、统计功效低，绝不代表显著则可实际投注。真实开奖过程若公平独立，所有模型的预测优势理论上都不存在。

## 八、后续阶段建议
