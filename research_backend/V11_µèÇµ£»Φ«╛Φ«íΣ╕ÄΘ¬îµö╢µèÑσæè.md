# PL5 V1.1 自进化解空间雕塑引擎（ESSE）——技术设计与验收报告

## 1. 系统边界

基于V1.0做**增量升级**。V1.0研发智能体继续负责发现规则、文献、创新代码和实验记录；V1.1 ESSE研究模块专注于**候选空间集合操作、逐刀解释、可撤销性、边际贡献、补回及全空间排序**。

`D:\pl5` 是用户Windows本地目标位置，本次只制作了可执行部署包，**未远程写入D盘**。

## 2. 算法定义

原始空间 `Ω={00000,...,99999}`，`|Ω|=100000`。第i把刀用布尔掩码 `B_i(x)` 表示该刀要剔除的号码。

启用集合 A、手动保护集合 P：

```
U(x) = OR_{i ∈ A} B_i(x)
S(x) = NOT U(x) OR (x ∈ P)
```

各规则掩码只读，不因某一次过滤永久修改。每轮按当前开关及顺序，从完整Ω重算，故**撤销不会丢失号码**。

- 单刀原始排除：`sum(B_i(x) AND x NOT IN P)`。
- 第i刀本轮新增排除：`|S_(i-1) ∩ B_i \ P|`，依赖刀具次序。
- **真实独有贡献**：`|{x: B_i(x)=1 AND Σ_{j ∈ A} B_j(x)=1 AND x NOT IN P}|`，与刀具次序无关；禁用该刀恰可恢复这些号码。
- 两刀重叠由`already_removed`显示；绝不简单相加各刀排除数。

`rank` 默认优先选择硬保留号码，组内多规则惩罚取最大值；同分通过固定种子哈希打散。若硬保留不足K，则用最低惩罚的被排除号码补回并单独打标签。用户显式保护的号码会优先进入最终候选集；如果保护数量超过K则中止操作。

分数及其归一化权重均为**未校准研究偏好**，绝不是经证实的中奖概率。

## 3. 工作台交互

1. CSV导入或伪随机演示数据，选择原空间或已注册的跨空间指标。
2. 配置历史时序窗口、模式、指标变换，并可加一条基础和值上限刀。
3. 启用/停用刀具、调序、建议贪心排序、权重调整、撤销/重做、保护单个号码。
4. 查看逐刀剩余、重叠、独有贡献、禁用后恢复数。
5. 生成完整100000注、Top-K候选及JSON审计报告。
6. 可选执行逐期只看过去数据的探索回测。

## 5. 关键安全与统计边界

- 严格验证模式必须经过**外部可信审计**提供准入键；标签文本不能成为审批凭证。
- V1.1不直接执行网络下载的Python代码，论文算法的开放式沙箱使用仍由之前的研究模块控制。
- 任何过滤刀下手前**并不知道未来中奖号**。在公平开奖假设下，K注的单期覆盖仍为K/100000。
- 历史反延续、稀有结构、映射编码只能产生可研究的假设；没有独立样本外证据不能以此宣称条件概率下降。
- 贪心排列建议只优化**展示路径**（更早显现大额压缩），不应混淆为预测能力优化。
- 可恢复操作仅覆盖当前Streamlit会话；跨重启持久化操作日志、签名审批门禁集成列为后续工程任务。

## 6. 验收项

- 不同掩码交叠、边际新增、独有恢复数；改变顺序不改变最终集合。
- 开关撤销、重做、保护号码、严格五位号码验证。
- 输出K注恰好K个；如果硬集合不足K，则报告补回数。
- 全10万号码、前导零、同组规则去重复惩罚、同分确定性破局。
- 严格模式无法凭`evidence='verified'`绕过可信审批；无规则时系统正常输出公平基线。
- 全项目旧版回归测试与V1.1测试全部通过；离线CLI生成CSV/JSON后检查文件。

**强调：工程测试通过，不等于彩票预测效果通过；真实官方开奖数据和独立前瞻验证仍需在用户端配置。**
