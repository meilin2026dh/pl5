# PL5 V0.4 · 多空间研究、规则竞争及映射稳健性系统

## 版本定位

在 V0.3 的基础过滤、历史时序反延续、23选6、41选4、11位310映射空间基础上，增加三项已落地的程序功能：

1. **多空间并行研究**：用户在同一次实验中选择多个空间、各空间的多种指标，统一观察最近历史的指标序列，生成各空间的反延续规则；空间内独立发现、空间间轮流使用全局规则名额，防止一个空间抢占全部名额；输出完整的10万号码评分表。
2. **多空间规则竞争**：计算每条启用规则的原始剔除比例、按固定顺序计算的边际剔除数、相对前序规则的冗余；计算每个空间规则的剔除并集、空间之间的Jaccard和Phi相关系数、重合最多的规则对；按期滚动、分别报告空间级和指标/模式/窗口级的实际剔除情况与条件随机基线。
3. **映射稳健性检验**：一个正式映射+多组由预固定种子生成的仿射单射映射，完全相同的窗口、指标、期号与参数，逐期前向评估Top-K命中和对数损失；比较不同映射的当前剔除集合Jaccard，避免事后仅挑选表现最佳的编码。

所有输出是统计研究结果与启发式评分，不是经过证明的中奖概率。若开奖机制公平、独立且均匀，则任意固定号码的条件中奖概率始终是1/100000；持有K个不同号码，命中概率K/100000。

## 一、统一指标入口

见 `pailie5/multispace.py`：`select_indicators`、`multi_space_study`。指标命名规则：

- 原空间：`sum`, `span`, `odd_count`, `digit_1` 等；
- 23选6：`pick23_6__sum`, `pick23_6__span`, `pick23_6__odd_count` 等；
- 41选4：`pick41_4__sum`, `pick41_4__consecutive_pairs` 等；
- 11位310：`ternary11__three_count`, `ternary11__switch_count` 等。

数字变换：`raw/mod2/mod3/mod5/mod10`。模式由原 `pattern_rules.py` 的 `PATTERNS` 提供，支持连续同值、严格上升/下降、等差推进、两期或三期周期、升降交替、低多样性。窗口3~12期可选。核心过滤处理沿用之前的规则保护，不允许模式判断使用待开奖期的数据。

对于每个空间，独立运行原有过滤规则发现；经过空间间轮询分配参与排序的规则名额。这样某个映射空间在规则检出量较多时不会自然排挤其他空间。

## 二、竞争与去冗余策略

- 原始覆盖：`#满足某规则的号码 / 100000`。
- 边际剔除：该规则命中且尚未被更早规则命中的号码数量。**顺序依赖，不可解释为模型独立贡献或因果解释。**
- 重合：两个剔除集合的 `Jaccard = 交集/并集`。若没有并集，则空间重合指标按0展示，不代表不存在关系。
- Phi：对两个二值剔除标签计算皮尔逊相关。任一边没有方差时报告 `null`，不伪造相关系数。
- 多空间评分：单指标内部对重叠规则取最大惩罚；同一空间内对指标求平均；不同空间等权平均。不同空间不是独立的证据，不进行概率乘法。
- 报告同时保留每个空间的分量得分及各规则的覆盖、重复与边际覆盖。
- `competition_backtest`：对每个待验证期 t 仅使用1...t-1期生成规则，记录空间联合被剔除概率与各个规则模板的条件剔除覆盖率。每期基线是当期剔除集合规模/100000，而非固定的单个命中率。

注意：不断调整同一历史回测窗口会发生数据窥探。回测结果仅用于算法迭代与排错，**正式验证必须先预注册并封存数据，再用新的未来开奖进行验证**。

## 三、映射稳健性技术细节

见 `pailie5/mapping_robustness.py`：

- 每个映射使用公式：`rank = (a * id + b) % space_size`。`gcd(a,space_size)==1`，保证一一映射；只使用对应10万个合法目标状态；其他组合不得映回PL5。
- 第0组始终采用V0.3的正式映射 `(a,b)`；后续组由SHA-256固定种子生成，绝不根据历史效果搜索最优映射。
- 对每期 t，先依据历史 `history[:t]` 构造反延续惩罚，然后计算实际开奖号码的100000号码相对名次；所有映射使用相同测试期、窗口、规则与Top-K。
- 检验评分时，综合惩罚的指数归一化权重仅是实验分配权重。对数损失对照始终是 `log(100000)`。
- 当前剔除集合计算Jaccard；**双方都未触发任何规则时，Jaccard报告 null（无信息），而非伪造“100%稳定”**。
- 报告公开映射乘数、偏移、对照种子、配置指纹、逐期明细。不得事后选择表现最好的对照当作“正式映射改进”。

## 四、运行

Windows PowerShell（项目已部署至D盘后）：

```powershell
cd D:\pl5
uv sync --python 3.12 --extra agent --group dev
uv run pytest -q
uv run streamlit run phase2_app.py
```

Streamlit左侧页面栏选择“04 多空间竞争与稳健性”。

离线命令行使用合成数据：

```powershell
uv run python multispace_cli.py --csv data\synthetic_demo.csv --demo --out runtime\v04_demo --competition-periods 12 --holdout 12 --variants 5
```

生成：`runtime/v04_demo_rank100k.csv`、`runtime/v04_demo_rules.csv`、`runtime/v04_demo_report.json`。

正式历史数据请先从官方公告人工核验、整理成 `period,number` CSV，并去掉命令里的 `--demo`；软件没有自动把演示数据伪装成真实开奖的功能。

## 五、数据安全与本地部署

升级脚本 `install_to_D_v04.ps1` 在 `D:\pl5` 已存在时，会将将要覆盖的每个旧源码文件提前备份到 `D:\pl5_backups\...`。原 `D:\pl5\runtime`、`D:\pl5\data`、`.venv` 与 `archive` 一律不覆盖或清理。无法创建备份即中止；不会修改全局Python环境。

## 六、验收边界

- 程序能分别读取四个空间的指标并进行10万号码统一排序；完整结果无缺失、无重复，`model_weight`归一化为1，而 `fair_probability` 固定1e-5。
- 规则竞争的集合并集、边际剔除数和Jaccard在构造样本上可复算。
- 所有预固定映射单射且可复现；正式映射生成的数据与旧映射完全相同。
- 时间穿越测试：在末尾添加一个未来号码，不改变任何过去验证期的结果。
- 对公平模型不宣称概率优势；无信号时分配均匀的主观权重。
- 未包含未经官方核验的开奖数据；未在用户Windows本机安装或启动。

## 七、下一版本研究方向

V0.5可把每条规则从研究卡片、固定版本、独立基线、回测及审计记录到知识库，同时将自动文献发现智能体的研究建议登记为**候选算法**；未通过人工/科学审计的算法不得更新正式算法注册中心。
