# PL5 V1.5.1 系统联调与验收记录

## 已解决

- 科研状态信息不再只能通过Python CLI查看。
- Node代理可在同一前端域名提供状态响应；浏览器不需要直接访问Python端口。
- SQLite状态只读，未配置或缺失的账本不会被UI查询自动初始化。
- 官方开奖缓存状态明确区分fresh / stale / invalid；不把来源URL标记视为来源真实性的独立证明。
- 安全升级为特征标识与源码锚点校验，不自动覆盖用户修改，也不修改GitHub main分支。

## 未解决（下一阶段优先）

1. 完整原始五序GitHub源码需要Windows首次在线克隆或由用户先行克隆。当前ZIP提供的是融合代码与原有四个已核验核心文件，并不是GitHub完整仓库副本。
2. Windows实机需要验证：Node24、pnpm11.25、`pnpm test/typecheck/build`、React状态面板与正式官方历史数据交互。
3. 长期运行需要把前向封存的“算法、候选集合、截止期、历史指纹、源代码版本”合并到一套可信实验台账；目前只显示V1.5竞争报告。
4. 增加官方数据增量归档和跨版本快照冲突报告，而不能仅依赖浏览器及服务端缓存。
5. 探索算法仍须严格样本外验证；结果没有优于随机基线的证据时维持均匀回退，不因压缩到100注而宣称概率增益。

## 不变边界

统计罕见模式不必然更不可能出现在下一期。系统的科研状态、模型评分、规则重叠、集合几何覆盖，均不能直接证明预测能力。自动审批和自动投注持续禁用。
