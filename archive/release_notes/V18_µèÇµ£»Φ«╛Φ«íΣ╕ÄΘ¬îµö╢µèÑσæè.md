# PL5 V1.8 技术设计与验收报告

## 目标与实施范围

从“算法是一段过滤代码”升级为“算法是可发现、可说明、可编排、可审计的能力”，复用此前智能体化物联网讨论中的能力目录和能力依赖图思想。此V1.8的协议UACP只属于PL5内部实验性草案，不是外部行业标准。

## 核心协议

| 字段 | 目的 | 安全限制 |
|---|---|---|
| id/version | 唯一身份、追踪派生关系 | 已注册内容不可同ID覆盖 |
| op/params | 支持metric / pattern / anti_filter / merge_masks | 固定白名单、类型和参数检查 |
| requires | 明确前驱及类型 | 依赖只能指向已存在能力，因而形成DAG |
| input_type/output_type | 自动编排时进行静态检查 | 不接受网络网页或LLM文本直接当可执行能力 |
| origin | 论文/代码/创建者来源标注 | 来源标签不是签名证明 |
| evidence/status/limitations | 研究与使用边界 | 不允许自行填写“预测优势已验证” |

能力元数据存在SQLite `capabilities` 表，SHA256用于本地完整性自检；日志存于`runs`表（不是不可篡改第三方见证）。

### 示例运行链

`pl5.metric.sum → pl5.metric.sum.pattern_arithmetic_3 → pl5.metric.sum.anti_arithmetic_3`

假设历史三个和值为18、20、22，新算法预测会继续形成等差的指标值24，列出10万注中和值24的全部号码作为**待反延续排除实验**。该规则的科学假设并未被证明，公平随机开奖不支持“历史连续必然终止”的概率推断。

## 运行限制与安全

1. 目前可自动生成的仅是受约束参数族，不是无界发明数学理论，更不等于证明彩票可预测。
2. 当前原版五序完整仓库只能由安装脚本在Windows联网克隆；本ZIP的`github_vendor`仅含前期核验的核心模块。实际TypeScript全仓构建仍须在本机验证。
3. 官网API的可用性、网络配额和真实运行周期未在当前会话实机验证；没有直接访问用户D盘或启用任务计划程序。
4. 所有算法即便运行通过，也仅能进入研究池。要用于证据约束模式需独立长期前向试验、版本审计和人工审批。
