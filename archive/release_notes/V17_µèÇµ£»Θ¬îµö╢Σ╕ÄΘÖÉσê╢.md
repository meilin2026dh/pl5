# PL5 V1.7 — 研发记录、验收与限制

## 研发范围

1. 在已有 `autoresearch.integrated_v10.ResearchCoordinator` 上增加 `autoresearch.supervisor_v17.Supervisor`；继承论文发现/假设创造/受限算法候选/开发证伪的阶段检查点，不能自动批准研究结果。
2. 新增 `official_archive_v17.py`：只对固定 `webapi.sporttery.cn` 地址发送请求、校验响应和排列五彩种编号350133；对历史冲突采取拒绝策略，生成不可原地覆盖的摘要快照。
3. 新增 `research_v17.py` CLI：明确离线/在线选择、恢复旧周期、只读状态、数据档案检查。Windows永久每日多触发器不设1天执行期限。
4. 将科研状态以只读 `autonomous_research` 字段注入现有 `/api/esse/status`，新增五序前端状态面板；保留原有V1.6页面。

## 核心保护

- 对同周期配置做摘要签名，执行完成的阶段不重复；失败阶段可续跑，成功报告绑定同一研究周期。
- 官方网络故障仅能降级到“研究资料检索”，不在未更新数据上伪装为完成了新一期开奖验证；数据格式或历史冲突必须报错停止。
- Linux/Windows跨进程互斥锁，任务进程异常退出由系统解锁；SQLite持续保存失败理由及各阶段尝试次数。
- 所有论文/新闻/GitHub结果是非可信数据；不自动运行外部代码。算法研究进入候选库，但未取得基于未来开奖的预测优势证据。

## 检验协议

- 本地使用离线fixture测试官方返回内容、重复/冲突记录、版本归档、损坏快照阻断、断点重试、同周期去重、配置变化拒绝及读-only状态；测试不访问互联网。
- 使用原 `research_v10.py` 七步工作流完成一次端到端离线演示，并在不重复执行阶段的情况下再次运行。
- 复用V1.6既有全套Python测试，并验证前端增量补丁可重复安装、不覆盖用户修改。
- 当前执行环境无法访问GitHub外网，也无法直接操作用户的D盘。因此真实官方API联机、新版Windows调度持久化、Node24/pnpm11完整生产构建、浏览器端点击均需用户电脑实机验收。

## 风险与后续

- 运行记录的本地时间/哈希无法单独提供由第三方认可的开奖前时间证明；如需可靠外部时间认证，应增加可信公开提交/签名及审计流程。
- 同一研究周期只能采用冻结配置；要改变检索主题或实验参数，应新开周期。
- 由于彩票样本稀少、海量候选算法导致多重检验，必须继续保留随机基线、封存留出与独立前向样本审查。
- 公平独立开奖条件下，100注单期覆盖率固定为0.1%，不因规则数目增加而改善。
