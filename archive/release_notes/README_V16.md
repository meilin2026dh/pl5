# PL5 V1.6：算法价值与动态权重中心

**版本定位**：在 V1.5.2 五序/ESSE 融合平台上增加 **只读、可审计的“逐刀价值评估与动态研究权重建议”**。不增加未经验证的中奖概率宣称，不修改历史封存，不自动启用/批准/停用任何过滤刀具。

## 功能

1. 从原有 `runtime/sculpt_evidence_v152.sqlite` 读取固定封存记录和开奖后结算记录，校验哈希链；只评价从最早封存期开始的**连续已结算前缀**，后面待结算期不能跳过。
2. 每把过滤刀独立计算：实际误删次数、按当期完整十万号码空间计算的公平期望误删次数、首次误删次数、与其他刀都不重叠的误删次数（独有误删）。
3. 读取最近一次已结算的完整 100000 位掩码，计算空间重叠与几何独立度，并避免把“相同刀具换名字”当成新信息。
4. 使用预设的样本门槛和保守偏差界，提出范围 **0.8—1.2** 的**实验性研究权重**；样本不足、未得到相应证据时权重 **固定1.0**。它不是开奖概率或投注建议。
5. 生成研究任务优先级：检查异常误删、用未见数据复核、去冗余或继续收集未来证据。
6. 通过现有 `/api/esse/status` 同源只读接口交给五序的 React `ValueCenter` 面板，保留现有所有功能。

## 数据约束

- 对第 t 期每把刀：`E_t = 此期预先封存的排除掩码实际位数 / 100000`，总期望 `Σ E_t`，而非把误删次数除以仅剩的100注。
- 一期实际开奖号是否被规则独立排除，按当时原始掩码检查；首把误删受规则顺序影响，**独有误删**不受顺序影响。
- 对同一把刀，最新几何独立度 = `这把刀排除且其他同期刀未排除的号码数 / 此刀排除号码数`；仅是结构重叠评价，不是预测信息量。
- 默认至少100个该刀的已结算前向样本，否则保持中性；预设诊断偏差界：`sqrt(n * ln(2m/alpha) / 2)`，m是当前刀具数。属于固定截点的保守诊断，不覆盖重复查看/变更算法/事后挑选后的错误率。
- **权重不会直接用于正式选号**。发现异常仅生成审查提案，不能从历史优胜据此声称有未来优势。
- 预先封存仍然只是本地证据，不具备可信第三方时间戳。

## Windows部署

1. 下载完整部署包后解压，双击 `install_to_D_v16.bat`。程序安装到 **`D:\pl5\research_backend_v16`**；原有 `frontend` 复用，缺失时从 GitHub 克隆并固定到先前审核的基准提交。原有的 `data`、`runtime` 及旧版后端不覆盖。
2. 执行 `验证_V16.ps1`，测试Python、Node/pnpm环境下的原生五序构建及前端回归。
3. 分两个PowerShell窗口启动 `启动_V16_科研后端.ps1` 与 `启动_V16_五序前端.ps1`。
4. 浏览器进入 `http://127.0.0.1:5173/workbench`，在 **“算法价值·动态研究权重中心”** 刷新数据。

### 命令行独立分析

```powershell
cd D:\pl5\research_backend_v16
uv run python research_v16.py --db D:\pl5\runtime\sculpt_evidence_v152.sqlite --min-periods 100 --alpha 0.01 --output D:\pl5\reports\v16\value_report.json
```

如果当前尚无已封存/结算数据，页面显示无数据或中性建议，这是正确行为。`examples/V16_合成数据价值分析示例.json` 使用**合成数据**，仅用来核对软件路径，不能作为预测能力证明。

## 集成与保护范围

- React页面通过 `integration_tests/upgrade_github_overlay_v16.py` **增量添加**，遇到用户修改冲突会拒绝覆盖，成功重复安装不产生重复组件。
- 本版新的Python API为 `pailie5/value_center_v16.py` 的 `analyze()` 与 `propose_research_weight()`。
- `status_v151.py` 的原有schema与`forward_evidence`字段完全保留，额外新增`value_center`字段，既有Node同源代理无需修改。
- 完整 GitHub 五序前端并未打包替换，沿用既有的已评审仓库和安全安装逻辑。
- 需在 Windows 上进行 Node24、pnpm11、uv、Docker（如要跑开放Python算法）及真实浏览器联调。本开发环境的Python测试不替代这些验收。
