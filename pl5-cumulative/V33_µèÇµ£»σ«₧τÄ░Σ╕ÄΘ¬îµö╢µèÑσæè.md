# PL5 V3.3 算子元学习引擎——技术实现与验收报告

**研究属性：** 有限数字运算表的数学结构学习；与彩票预测效果严格分开。 

## 1. 范围与版本差异

V3.2主要是在固定数学类别中生成假设。V3.3新增统一的结构S、参数θ、可证性质C三层模型，以及5种有界的学习器：

| 学习家族 | 结构学习 | 实际拟合的参数 | 严格界限 |
| --- | --- | --- | --- |
| 模轨道 affine_orbit | 选模轨道 | u、v、10元素函数表 | 1≤u,v≤9；枚举候选 |
| 分段轨道 piecewise_orbit | 方向和行分组 | 类别、轨道值 | 至多3组；迭代离散赋值 |
| 稀疏修补 sparse_exceptions | 选择基础轨道+例外 | 例外坐标、修正值 | 至多6个点 |
| 决策树 decision_tree | 学习分裂图 | 特征、阈值、叶标签 | 深度≤3；有限候选特征 |
| 连续量化 quantized_linear | 固定4项线性形式 | 常数、a、b、绝对差系数 | 线性规划+有界量化；系数绝对值≤20 |

可检验性质：交换律、双向平移不变性、反向平移不变性、与a无关、与b无关、**仅在输出子域上的**结合律。性质集目前预声明；智能体可以接受性质约束并拒绝不符的候选，但不会自主发明新数学公理。 

输入是`10×10`有限整数表，支持完整输出类别`0..2`或`0..3`，不支持无界实数域。学习出的能力只以`research_only`登记，不自动改变ESSE正式策略。

## 2. 数学验收协议

1. 随机封存20个真值表单元，使用其他80个单元诊断各类模型泛化误差；**这不是开奖时间外验证。**
2. 之后使用100格重新学习结构及其参数，要求重新生成的数学表与原始表在100个输入对上全部相等；不满足则拒绝登记。
3. 采用内部明确定义的MDL编码代理，只有表达长度小于整张表时登记；编码代理并不是zip压缩率，也不是普适最短描述长度的证明。
4. 交叉检验：数学表SHA256、逐格独立标量计算、向量计算及性质重新计算。
5. 每个能力有稳定ID和SQLite注册记录SHA256；禁止任意Python字符串执行，HTTP只接受有界JSON数学表。
6. AAN复合执行和ESSE研究掩码依然是**实验性集成**，不自动升级为彩票预测模型。

## 3. 可复现合成实验

由 `python research_v33.py demo` 产生：

| 数学真值表 | 是否存在精确压缩结构 | 找到的对应家族 | 代表性描述长度（bit代理） |
|---|---|---|---:|
| 模轨道 | 是 | affine_orbit | 52 |
| 两状态分段轨道 | 是 | piecewise_orbit | 75 |
| 两处例外点 | 是 | sparse_exceptions | 70 |
| 三叶小决策树 | 是 | decision_tree | 56 |
| 连续系数量化 | 是 | quantized_linear | 128 |
| 独立均匀随机表 | 否 | 无 | 不予登记 |

所有成功登记的例子都经过100格严格重构；随机表未被硬凑出“数学发现”。以上是**人工设计的数学实验**，并不代表真实彩票存在可预测性。

- 新模块、HTTP及V3.2/V3.1/V3.0/V2.9相关专项与兼容测试：**110项通过**，运行日志见 `V33_验收实录.md`；最终ZIP解压复测同组**110项通过**。

- 另一组V2.4–V2.8相关测试运行到约91%后超时，未计作全部通过。
- 仍须在Windows上实际执行安装、uv依赖同步和Streamlit可视化验收。
- 官方历史开奖来源校验和冻结后未来时间外的预测表现评估，**本版本未完成**。

## 6. 研究结论

这一版本的可证明成果是：**在有界的模型语法里同时学习类别、参数和可测试性质约束，并将精确且紧凑的表达登记为可复用数学能力。** 不能推广为“PL5全部既有参数已自动学习”，更不能从数学表压缩推导中彩票预测优势。若开奖独立均匀，则历史算法无法形成稳定的预测信息优势。
