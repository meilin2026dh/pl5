# PL5 V2.2 研发与分级验收报告

## 目标与实现

**研发目标：** 不再停留于V2.1只有角色任务卡和反例检查计划。实现受限自动编译，真正**可执行**的反例检查、Python/Node独立容器逐值交叉比较，以及科研结果不可变记录。

**原有平台：** GitHub五序前端、基础过滤、ESSE、论文来源、历史归档与V2.1委员会保持不变。新增模块只扩充科研研究路径。

**明确设计边界：** V2.2的自动生成是五类可信模板派生的程序，不是开放式自动发明任意论文算法。无算法预测优势的发现或验证，自动正式准入保持关闭。

## 实验架构

- 文献研究角色：固定原文SHA，明确方法名只作启发，不遵循外部网页指令；无法识别时拒绝发明。
- 两路Python工程：生成两份AST结构不同的`score_batch`实现，复用V2.1源码登记审计。
- Node异构工程：编译器固有的JS模板，禁止自动引入外部JS依赖；在`node:24-alpine`运行。
- 红队：零历史、3种极值/前导零、重复历史、候选集合排列变化、6号边界组合；可选择再扫描全部100000注。
- 规格审计：由完全可信的固定数学规格函数计算同一输入，检查Python主、Python参考、Node三者与规格的一致性。不会把一致性冒充数学模型已证实。
- 隔离：用户显式`--allow-docker`，不允许宿主执行外部代码，分别使用两个容器，关闭网络、全部Linux capabilities、限制内存/CPU/进程数。Docker缺失时明确失败。
- 证据持久化：项目源码、公式族、实验输入指纹、全部逐值检查和SHA256不可修改。可重复查询，但同一项目拒绝第二次封存测试以防反复挑选结果。

## 实测测试（当前开发容器）

| 项目 | 实际结果 | 限制 |
|---|---|---|
| V2.2自动生成+规格/差异故障注入 | 9项通过 | 注入测试执行器是可信测试替身，不是Docker实跑 |
| V2.2本地HTTP只读桥接 | 1项通过 | 仅本地loopback |
| Python完整回归，分4批 | 69 + 87 + 66 + 71 = **293项通过** | 单次完整执行超过执行超时；分组真实执行且无跳过 |
| GitHub前端增量升级集成套件 | **29项通过** | 测试前端补丁，不是完整网页端E2E |
| 5类Node自动源码静态语法检查 | **全部通过** | Node 22语法校验，不是Node24容器运行 |
| Python/Node Docker双运行时 | **未验收** | 当前执行环境无Docker引擎 |
| Windows D盘实机安装及定时任务 | **未验收** | 无法直接操作用户的Windows主机 |
| 真实官方数据/未来开奖显著性 | **未验收** | 没有真实前向结果 |

## 主要待解决事项

1. 在真实Windows本机审查并实跑Docker双容器、确认生成代码与参考数学公式逐值一致。
2. 增加自动负例构造的广度和多种超出模板的数学算子，但每个都必须绑定独立可核查数学规范。
3. 更完善的LLM辅助源代码建议与实验授权/成本预算、反提示注入测试和故障恢复。
4. 真正不同研究团队从论文原公式独立复现；三份编译器共享公式不能替代科学复现。
5. 接入前向封存记录，检验规则是否在真实未来开奖中超过`K/100000`基线；不能因为10万注被压到100注就宣称胜率提高。

## 科学口径

在公平独立均匀开奖条件下，任意固定100注下一期开奖概率为0.1%，十期至少命中一次约0.9955%。本版唯一验证的是工程能力，**没有任何新证据**证明能够将其提升到“十期内必中”。
