# PL5 V2.0 技术设计与阶段验收

## 核心改动

| 功能 | 实现文件 | 验收口径 |
|---|---|---|
| 论文方法证据锚点 | `autoresearch/paper_factory_v20.py` | 引文必须逐字存在于已登记的文本快照；原文摘要不得宣称作者方法复现 |
| 默认自主方法提取 | `PaperFactory.auto_extract` | 同文献、同方法内容幂等；只提研究线索，不生成/执行外部代码 |
| 受控LLM创作 | `llm_blueprint`、`research_v20.py` | 未显式授权不调用；生成的引用再次逐字验证；代码通过原有AST审核 |
| 双代码隔离复核 | `PaperFactory.link_code/study` | 主实现/参考实现哈希不同；每份运行两次；Docker无网络/只读/资源上限；结果去重且属于输入域 |
| 科研能力说明书 | `PaperFactory.capability_card` | 存储原文证据、依赖、接口、源码哈希及研究状态；不会自动发布到ESSE |
| 五序UI只读状态 | `PaperFactoryV20.tsx`、`integration_server.py`、`esseProxy_v20.mjs` | 同源API代理、不可跨任意域转发、显示实验/未验证标识 |
| 安装与定时 | `install_to_D_v20.ps1`等 | 保护已存在后端、现有GitHub本地修改和旧数据库；需要用户显式启动 |

- V2.0论文研究专项：9项全部通过（原文真实性、摘要约束、重复注册、付费授权、双实现差异、不可变审计、隔离拒绝、非法输出阻断、只读HTTP状态）。
- 后端完整回归：分3组执行，114 + 83 + 73 = 270项通过；增加2项HTTP后共272项。全量一次运行因时限未得到汇总结果，分组完整覆盖所有测试文件。
- GitHub增量升级兼容：24项集成测试全部通过；包含新前端安全安装、重入、用户修改冲突保护。
- `node --check github_overlay/server/esseProxy_v20.mjs`通过。
- 命令行端到端：真实创建文献记录、提取原文、注册两份例程、生成UACP科研卡并读取状态（使用合成教学文档，无Docker执行）。

**尚未验收**：Windows本机、完整GitHub前端构建、真实Docker容器执行、在线arXiv全文下载、付费LLM API真实调用、官方开奖数据增量同步、长期定时任务及未来开奖号码验证。

## 风险及待办

1. 默认自动摘录仅是一条真实引用的研究线索，不能自动推导作者完整算法。即使付费LLM生成了源代码，仍需人工核对论文的参数和方法。
2. Docker隔离降低风险但不是绝对沙箱。建议部署时再对镜像digest固定、超时/CPU/内存、磁盘和容器版本做实机验收。
3. SQLite中的方法卡和研究报告拒绝修改或删除，但不构成可信第三方时间戳。论文出处核实、开奖前时间见证仍需另做。
4. 研究者每次选模都会增加多重测试负担；不能使用相同历史结果自证超过随机基线。
5. 引文截取与外部开放论文的版权政策需依来源遵守；方法卡仅保存短片段与来源哈希，不保存非授权整篇论文到用户可视UI。
6. 后续可在明确资源预算与人工审批下，增加“论文公式—受约束算子”自动转换、异构独立参考实现和Docker实机证明；不要为了算法数目而反复生成等价方法。

公平独立开奖下，任何开奖前选择的100个号码，其单期命中概率均为100/100000；10期至少命中一次的随机基线为`1-(1-0.001)^10≈0.9955%`，不能宣称自动科研可保证10期中奖。
