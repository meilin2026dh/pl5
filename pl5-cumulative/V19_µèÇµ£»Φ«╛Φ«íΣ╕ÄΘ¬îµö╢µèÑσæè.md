# PL5 V1.9 设计、实施与验收记录

## 研究目标与真实实现

在原AAN中增加一个**目标驱动的新指标创造工厂**：分析既有能力数量和所需依赖，自动生成可安全解释的JSON表达式，跨两种独立计算实现做100,000/100,000逐号核对，识别指标分组等价关系。通过工程校验的表达式登记为`metric → pattern → anti_filter`三节点能力链。不得自动产生已验证预测优势的声明，也不向彩票下注接口发送命令。

核心程序：`pailie5/ability_lab_v19.py`、`ability_cli_v19.py`、`research_v19.py`。与旧版`capability_network.py`兼容，新增`metric=expr`，仅接受白名单、安全参数和有界深度的运算树；`eval`、动态导入、外部Python执行均未使用。

### 工程准入与证据分层

| 结果 | 实际意义 | 不意味着 |
|---|---|---|
| 双实现逐号一致 | 指标计算准确性得到独立的工程复核 | 中奖概率提升 |
| 10万号指标分区不重复 | 产生不同的号码分区特征 | 特征与开奖相关 |
| 开发期前序回测 | 检查模式是否在历史上曾延续，记录期望误删与观察误删 | 独立前向验证或显著性确认 |
| 登记AAN研究能力 | 可被发现、编排并在ESSE探索模式使用 | 允许进入正式的证据约束过滤 |

### 已知限制

- 研究目标规划目前为四类预设方向，仍需进一步接入真实论文语义解析与能力需求本体。
- 新指标可在受限数学语法中自生长，但不能任意创造新的神经网络或数学算子；固定语法空间最终会耗尽。
- SQLite使用哈希完整性字段，不能独立证明记录创建于开奖之前；仍需外部可信时间戳/不可回填前向证据。
- 用户本机数据范围及官方接口可用性未在当前容器实测；外部Github源码需要Windows联网安装或本机已有完整克隆。
- 没有Docker，不测试任意外部源码的沙箱运行；**本版不执行外部源码**。
