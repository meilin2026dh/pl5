# PL5 V3.7.4 自主科研循环设计

## 目的
将已运行的 V3.7.3 有界数学表达式搜索，变为一个可在用户环境重复执行、保存证据、按结果提出下一实验的科研代理。当前实现是**离线、确定性、有界自主实验**，不等于可以无监督发明任意数学原语、修改代码或预测开奖。

## 已选方案
复用 Python `pailie5.ablation_search_v373.fit_budgeted`、V3.7.2 冻结算子和 V3.7.3 数据生成器，新增只做流程调度的控制器。这优于新增不兼容 LLM 实验栈（难验证、涉及 API 成本），也优于只执行静态批量脚本（不能依据上轮结果决定研究问题）。

## 运行协议
- 训练60/封存40个10×10输入对，冻结全部对照候选以后才打开封存结果；每轮数据使用不同随机种子。
- 等候选预算比较 full、no-warm、selective-warm、grammar-only。选择性知识库只准根据训练60格评估和筛选候选表达式。库源严格为历史冻结公式及其有效子表达式。
- 每轮运行前先落盘下一实验配置、数据指纹与研究假设；执行后保存冻结算子、独立封存评估、诊断与下一轮问题。工作目录只允许新增文件；禁止覆盖既有证据。
- 按弱项与公平探索选择下一种合成数学任务，定期插入纯随机负对照。若发现训练拟合但封存失效、预算未达标或测试错误，记录问题与对策；拒绝自动将异常拟合当作发现。
- 每轮CPU预算上限、最大轮数固定；禁止自动执行生成的代码、外部联网、自动投注、自动写入生产过滤器。未来要持续无人值守，只能在用户本机明确安装定时任务或外部调度。

## 明确不做
- 不用同一封存集在下一轮调参后再声称独立验证；跨轮复用任务家族只能算探索，不当作预注册确认试验。
- 不自动调用远程模型或花费API费用。
- 不会把沙箱进程描述为持续后台服务。

## 验收
测试覆盖: 已知结构及随机对照；训练与封存严格隔离；连续运行新种子；中途状态恢复不覆盖；生成问题日志；历史后端回归通过；生成可直接运行CLI与Windows定时任务示例（默认不安装）。
