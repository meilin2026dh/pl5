# PL5 V3.7.17 — 端到端性能研究与可复现实验报告

## 研究目标与因果归因

上一版V3.7.16已证明精确位图在规则交集场景有价值，但在滚动排序/雕刻流程上未显示稳定提速。用cProfile抽查完整科研代码后发现，十万行Pandas表格构建、号码字符串化、真实号码表格检索，以及跨期指标重复计算消耗明显。本版对这些非算法必要步骤建立独立的**可选轻量回测路径**。

这次没有减少参与排序的候选号：两条路径仍对10万注全部计算后完整排序；只有排序完成后才使用被测期开奖号码查询排名，遵守时间前向与完整搜索空间的约束。

## 源码范围

- 修改 `research_backend/pailie5/probability_ranker.py`：新增 `RankTargetSnapshotV3717` 和 `rank_target_snapshot_v3717`，`rolling_rank_backtest(...,target_only=True)` 省去滚动回测中为查询实际目标而生成全表的Pandas和号码字符串操作；原默认参数为`False`。
- 修改 `research_backend/pailie5/sculpting.py`：新增 `SculptSession.rank_target_snapshot_v3717`，`rolling_sculpt_backtest(...,target_only=True)`，保留完整`sculpt()`、惩罚汇总、词典序排序、配额恢复和相同的摘要统计。
- 修改 `research_backend/pailie5/pattern_rules.py`：`filter_next(...,optimize_context=True)` 仅在**同一调用内**按指标缓存历史/候选跨期原始值，并在规则应用阶段复用经变换的全域特征。默认值`False`保留旧执行路径；不跨不同期保存历史状态。
- 新增 `research_backend/benchmark_research_performance_v3717.py`，提供按种子运行的完整科研流程旧新对照与逐字段、逐结果摘要哈希一致性校验。
- 新增两组专项测试：`test_target_only_v3717.py`与`test_research_performance_v3717.py`。

## 两轮实际端到端实测

使用同一 `data/synthetic_demo.csv`（1000期**合成数据**，并非认证彩票历史开奖）；两个固定执行顺序种子3717、3718，**各10次重跑**。基线和新版共享相同配置、同一内存会话及基础条件位图catalog。严格比较完整回测报告、过滤结果以及规则审计。先进行非计时暖机，每次交替顺序测量`perf_counter_ns`，不把单一函数微基准等同端到端加速。

| 科研工作流 | Seed 3717：旧→新 | 加速比 | Seed 3718：旧→新 | 加速比 |
|---|---:|---:|---:|---:|
| 5期滚动排序 | 265.08 → 72.20 ms | 3.67× | 268.94 → 66.50 ms | 4.04× |
| 5期滚动雕刻 | 356.48 → 191.83 ms | 1.86× | 356.21 → 177.16 ms | 2.01× |
| 3期复杂时序模式识别 | 3810.95 → 864.13 ms | 4.41× | 3791.72 → 803.64 ms | 4.72× |

不同工作流中位耗时相加的描述性比值：**3.93×、4.22×**。该汇总不是一项独立完整作业的总体运行时间，只用于比较等权选择的三类任务。对三项工作流，各20次的结果严格一致（总计60次新旧对照），并在执行正式基准前分别核实完整输出。

## 真实性与边界

- 历史数据为包内合成演示数据（SHA256 `f7812094b6a4c7f6a8b10676c1b6ab95e3a234efdede9ff2786319a2fefc6ff6`），**没有使用真实、认证的排列五开奖历史进行统计预测验证**。
- 轻量化只优化报告生成和重复计算，不改变任何公平彩票的数学中奖概率，也不等价于提升号码预测能力。
- 默认旧路径保持不变。若外部注册的上下文指标含有副作用或读取未冻结的外部状态，`optimize_context=True`不能保留原调用次数；该加速只适用于**纯函数/确定性**指标，并应在输入更新后重新计算。
- 性能数字仅反映当前Linux/Python运行时、合成历史和选定配置，Windows需独立实测。
- 按理论，独立均匀开奖下购买K个不同号码的头奖命中概率是K/100000；本次研究不提供超越这一基线的证据。
