# PL5 V3.7.27 科研与工程验收报告

## 研究任务

本版把 V3.7.26 的“完整拟合后再按 CPU 时间筛选”，升级为 **子进程实际强制 wall-clock 截止**。两个算法各在全新 Python 进程中运行；进程启动、依赖加载、拟合、验证集冻结、证据落盘全部算入限制。任何超时/失败的部分结果均不得参与持出评分。采用从出题/求解/评分三方拆分的文件接口，但内部演示仍共用开发者的工作机器，**不能称为真正独立第三方盲测**。

## 数据和协议

- 开发者编写 8 类合成任务 × 2 个种子，共 16 组；每组 48 格训练、16 格验证、36 格持出。含 12 组结构类、2 组独立随机表、2 组现有语法不可表达的指数类结构。
- 每组先由出题侧生成公开数据与私有持出数据；求解脚本只传公开数据文件路径，完成算法冻结并写入状态清单后才启动结算端；保存私有数据，仅为**内部可复现演示**。
- 两个算法分别为 V3.7.25 环代数、V3.7.26 条件门控。冻结组合只在两者均于各自时间预算内完成时才考虑，按双模型预算计费，不与单模型视为等计算成本。
- 预算分别为 800 ms 和 3000 ms / 模型；超过预算的子进程被终止，全部计入 16 组分母。训练特征、模型来源与参数发现成本未计入。
- 结果详见 `runs/v3727/internal_hard_budget/protocol.json`、`results.csv`、`summary.json`；中断运行的痕迹已保留，随后分段完成全部32组（16任务×2预算）。

## 结果

| 模型 | 800ms：正确完成 | 3000ms：正确完成 | 3000ms：持出错误 |
|---|---:|---:|---:|
| V3.7.25 | 0 / 16（16次超时） | 6 / 16 | 0 / 216格 |
| V3.7.26 | 0 / 16（16次超时） | 10 / 16 | 0 / 360格 |
| 两模型冻结组合（预算上限 2倍） | 0 / 16 | 12 / 16 | 0 / 432格 |

在 3000ms 的任务上，两个独立模型实际 wall-clock 中位数约 1.34 秒。800ms 下全部超时，说明 Python 新进程冷启动成本不可忽略。未将 0/16 视为数学能力下降，也未把 12/16 视为同预算胜过 10/16。

随机表和复杂未知结构的 4 组控制任务，两种算法以及冻结组合均弃权。所有任务均是**开发者知道生成公式的合成题**，因此未取得外部独立未知任务盲测证据。

## 复现、回归与缺口

- 第一阶段增加 18 项自动化测试，涵盖不可覆写、强制超时、私有答案提交、SHA256记录的普通篡改检测及失败不计入评分。
- 完整历史测试文件共 111 个；因单次完整命令未能在执行窗口内完成，将同样文件集划分为 10 组执行。分组退出码全部为0，**合计 1092 / 1092 项通过**。该说法不等于同一进程的单命令验收。
- 选取条件门控、三次结构、随机表、复杂幂结构4组、在 3000ms 时间上限重跑；12条结算的冻结状态与错误数与原运行一致，时间测量本身存在正常波动。
- 通过 ZIP、逐文件 SHA256 和增量补丁还原审计后发布本版交付文件。

## 不能推导的科研结论

1. 没有外部机构/独立未知测试题交付，文件 SHA256 不是可信签名或第三方时间戳，不能用包内私有答案冒充第三方盲测。
2. 不是总科研成本对照：历史发现/人工研发、训练任务生成、第三方组织、部分设备能耗与结算流程不在预算内；组合模型预算翻倍。
3. 16组内部任务的“0错误”受条件接受/弃权机制限制，不能外推为数学难题普遍准确率。
4. 现实开奖若均匀独立，算法复杂化不会提高同投注注数的中奖概率；本研究尚无预测优势。
5. 未在 Windows `D:\pl5` 实机运行，未推送GitHub，未开展长周期未来开奖前的独立封存验证。
