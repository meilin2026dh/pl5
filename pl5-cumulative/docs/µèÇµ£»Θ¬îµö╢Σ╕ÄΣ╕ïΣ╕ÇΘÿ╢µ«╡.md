# PL5 V1.2技术验收与后续融合计划

## 验收范围

- GitHub: `src/domain/pick5.ts`、`src/domain/backtest.ts`、`src/domain/audit/engine.ts`、`src/domain/research/tuning.ts`、`src/domain/evidence/engine.ts`、`server/provider.ts`及界面入口等作为第一批复用对象。
- 接口：以 GitHub 原生 `filter(input)` 结果为“事实源”，将**每条启用规则在来源域内的保留集合**打包为10万位LSB0位图。
- Python: `integration_bridge.py`完成SHA256、严格交集校验、不可越域的配额修复、边际贡献、确定性随机并列处理、审计报告。
- 数据：前端官方开奖来源标签透传，但尚未升级为后端独立核实的官方签名快照。
- 统计：没有发现中奖概率优势，正式计算中明确保留公平数学基线。

## 风险项及解决策略

1. **原生规则本身的错误无法靠bitset SHA捕获**：必须扩展基准夹具，按和值、奇偶、跨度、历史边界与跨空间高级指标逐项进行异构独立实现比较。
2. **版本漂移**：补丁使用两个严格锚点；源码变动时拒绝修改并要求人工合并。
3. **后台开放代码**：V1.2不会运行用户上传的脚本或自动纳入研究候选。
4. **官方历史快照**：定时增量抓取必须在后续版本独立设计幂等性、跨源一致性、封存期号和历史修订处理。
5. **工作台容错语义**：V1.2明确拒绝`atLeast`和`violations`。V1.3建立统一`FilterExpr`与类型化布尔公式树后再开放这些模式。
6. **分数与概率混用**：审计里`statistical_status`明确是没有已确认预测优势；偏好惩罚分只用于研究性候选排序。

## 下一阶段 V1.3 验收目标

1. GitHub Actions执行TypeScript+Python双栈CI；发布兼容协议及全量规则测试夹具。
2. 同一官方历史库共享不可变快照与可核验期号截止；Python独立核验历史来源。
3. 规则表达统一，容错组/历史依赖/映射指标通过语义一致性测试。
4. 自主科研候选算法经开发集、封存验证、许可证、安全沙箱、人工审批后才发布到ESSE注册中心。
5. 前向封存持续对照`K/100000`基线，永久存档失败实验与未见测试记录。
