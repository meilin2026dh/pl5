# PL5 V3.7.7 研究与工程验收报告

## 版本与研究问题

基线：V3.7.6 Hotfix 1。核心问题：当通用符号表达式搜索在某类已知数学结构上泛化不足时，能否通过**从训练约束中归纳潜在一元数字映射**，恢复结构而非单纯扩大搜索量？

模型限定为 `f(a,b)=(u(a)+v(b)) mod 10`。新方法将每条观测视作二分图模10同余约束；含冲突圈则拒绝，不连通则弃权。该算法是经典模加法结构的训练数据因子分解，不应宣传为世界首次数学发现。

## 开发试跑与正式协议修正

第一次开发试跑错误地只变换了分割种子，未改变三个可分解任务族的目标表。该漏洞由 `test_structured_case_seed_changes_the_target_not_only_split` 在修复前红灯检出。旧结果仅保存为 `dev_pilot_*` 调试记录，不纳入正式统计。

正式阶段将每个目标函数的系数、常数设置为不同种子生成，固定协议存于 `protocol.json`，协议hash为 `d322c122aaebfcba75559cc4b7a5ab4003687867171ba5b1c8072e76d8fd3f3f`。

## 正式研究设计

- 3类预设加法可分解目标、2类非可分解目标、1类独立随机表；每类5个不同参数/数据种子，合计30张合成表。
- 每张10×10表70个训练格、30个独立保留格。模型拟合API只能接收70个已标注训练格；保留标签完全不进入拟合函数。
- 对照为已有 V3.7.2 安全表达式树搜索，训练上限每组500个候选评价，不读取保留标签。
- 两种算法计算工作量不同；不得将差异当作预算匹配的优劣结论。当前研究依然是由人工选择任务族的开发性基准，不是外部盲测或彩票未来数据实验。

## 正式结果

| 对照项目 | 本次结果 |
|---|---|
| 加法可分解结构 | 15/15张表识别成功，450/450个保留输入计算正确 |
| 两类非可分解 + IID随机负对照 | 15/15拒绝识别，不在保留集上强制预测 |

| 200张额外随机表 | 200/200拒绝（独立事后压力检查，不是预注册确认实验） |

禁止在随机负对照“拒绝预测”的情况下将其当作0%误差模型去与其他模型比较。系统只有“接受并拟合”或“拒绝”两类结论；不存在彩票过滤有效性结果。
