# PL5 V2.1 — 架构与阶段验收报告

## 本版目标

把V2.0的论文原文与双实现研究工厂提升为**可持续执行、可恢复、分工明确、可审计的多角色科研流程**，形成「论文证据 → 假设 → 能力缺口 → 双路实现 → 红队反例 → Docker配对实验 → 科学门禁」闭环。

## 数据治理与核心不变量

- 文献来源必须是V2.0登记且哈希固定的文献；方法摘录已逐字核验。
- 默认自动创建**计划**而不是自动生成不可信代码；新计划最多12项/轮。
- `primary`与`reference`采用原V2.0静态语法安全检查，完全相同AST的代码拒绝登记；不同AST不认证工程独立性。
- 禁止外部代码在主机执行；只有显式允许Docker后才调用旧版隔离执行接口。
- 正式算法库没有自动发布路径；即使工程检查通过，也只是待人工科研审查。
- 重复项目按能力卡ID、目标、预算、实验期数签名去重；同项目阶段产物不可改写。
- 科研任务列表和每一步日志经SHA256链校验；假设失效或研究方向变化时建立新研究项目。
- HTTP接口只读，不提供远程源码写入或未授权Docker调用。

## 完成的测试

- V2.1独立科研委员会与HTTP测试：11项通过（不含V2.0现有项目）。
- V2.0先前论文工厂专项测试：7项通过，与新版协同配合。
- 现有后端回归分组执行：106 + 98 + 68 = 272项通过（包含上述V2.0论文工厂7项），所以后端总计 **283项独立测试**。
- 前端安全覆盖安装集成测试：包含V2.1新测试，当前完整集成套件 **27项通过**。
- Node V2.1代理`node --check`通过。GitHub原前端完整pnpm/typecheck/build须在Windows实机验收。

本报告只陈述在当前执行环境实际完成的验证，不意味着Docker实机已运行、外部论文已自动忠实复现、官方开奖联机完成、付费LLM调用完成或真实未来预测提升。

## 应继续研发的方向

1. 使用隔离容器与测试夹具自动**执行**红队反例，而不是仅记录检查计划；
2. 两个真正异构的工程后端（如Python与TypeScript）进行逐值交叉验证；
3. 明确授权的多模型并行创造与任务成本预算；
4. 第三方开奖前时间见证与全流程前向样本登记；
5. 将候选UACP能力说明书与ESSE安全规则准入委员会联通；不得将研究性评分包装成中奖概率。
